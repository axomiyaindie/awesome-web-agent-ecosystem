# Contributing

Thank you for helping improve Awesome Web Agent Ecosystem!

We welcome useful tools, projects, standards, integrations, and practical resources that help AI agents interact with, understand, test, debug, and build for the web.

## Inclusion Criteria

A submission should meet these criteria:

1. **Relevant** — Directly related to AI agents working with websites, browsers, or web development workflows.
2. **Useful** — Provides a practical capability, integration, protocol, reusable workflow, or technical resource.
3. **Documented** — Has sufficient documentation to understand its purpose, capabilities, and usage.
4. **Accessible** — Includes a working official project page, repository, specification, or documentation link.
5. **Accurately described** — Does not exaggerate capabilities or claim unsupported compatibility.
6. **Responsible** — Does not primarily facilitate malicious activity, credential theft, unauthorized access, or harmful automation.
7. **Verifiable** — Has an identifiable maintainer, organization, specification owner, or authoritative source.

Actively maintained projects are preferred. Useful standards and stable reference documentation may be included even when they are not conventional software projects.

General-purpose developer tools may be included when they provide meaningful value to agentic web workflows. Clearly distinguish these foundations from tools specifically designed for AI agents.

## What Belongs Here?

Examples include:

- MCP servers and integrations.
- Browser agents and automation frameworks.
- Agent skills and reusable workflows.
- Browser developer tools and debugging integrations.
- Web documentation retrieval tools.
- Testing and accessibility automation.
- Web crawling, extraction, and research tools.
- Design and developer-tool integrations.
- Deployment and hosting integrations.
- Agent interoperability protocols and standards.

## What Does Not Belong Here?

- Standalone UI component libraries.
- CSS frameworks and styling utilities.
- Standalone design systems and component showcases.
- Icon, font, and illustration collections.
- Generic website templates.
- Design inspiration galleries.
- Unrelated AI model directories.
- Generic programming resources without a meaningful connection to web agents.
- Abandoned or inaccessible projects without sufficient historical or reference value.

## Adding a Resource

1. Find the most appropriate category.
2. Check whether the resource is already listed.
3. Verify the official project or documentation URL.
4. Write a concise, factual description.
5. Include relevant compatibility requirements and limitations when useful.
6. Identify whether the project is officially maintained, community-maintained, experimental, or archived when relevant.
7. Submit a pull request.

Use this format:

`- [Project Name](https://example.com) — A concise description of what it does.`

Prefer official upstream repositories, project websites, and primary documentation over third-party directories.

## Pull Request Guidelines

- Prefer one logical change per pull request.
- Keep entries alphabetized within each category where practical.
- Avoid unnecessary duplication across categories.
- Do not include unsupported claims.
- Do not add promotional language.
- Do not copy descriptions from other directories.
- Preserve existing Markdown formatting.
- Update category documentation when introducing a new category.
- Explain why a new category is necessary when proposing one.

## Security and Licensing

Do not submit resources that expose users to unnecessary security risks.

Where relevant, review project permissions, data handling, licensing, dependencies, and maintenance status before recommending a resource.

A listing does not constitute a security audit, endorsement, or guarantee of safety.

## Review Process

Maintainers may:

- Request additional information or corrections.
- Move resources to more suitable categories.
- Reject duplicate or out-of-scope submissions.
- Remove resources that become inaccessible, abandoned, misleading, or unsuitable.
- Reorganize categories to improve discoverability.

Inclusion decisions are based on relevance, usefulness, documentation quality, and alignment with the repository's scope.

Thank you for contributing!
